# Work Patterns

These are workflow preferences, not a public copy of private project settings.

## Windows And Setup

Inspect the current shell, paths, runtime, and installed tools. Use PowerShell syntax for a PowerShell host, not a guessed WSL path. Prefer an installed tool over a new dependency. Report the user/host/project scope of installation, preserve existing configuration, and verify discovery separately from file presence.

## Code And Games

Inspect the engine/framework and existing patterns. Build the requested usable experience and actual assets, not only a plan or decorative mockup. Choose an available game/asset specialist for its domain work rather than loading multiple game studios. Verify gameplay behavior and rendered output appropriate to the target; syntax checks alone do not prove a working scene. Preserve explicitly requested features while keeping the implementation simple.

## Local AI Images And Video

Read model, adapter, trigger, strength, seed, and acceptance settings from the project. Do not hard-code personal model paths or identity thresholds in this public skill. Check dependencies, run within the authorized resource budget, and inspect output. Numeric identity scores need visual review; file hashes do not prove quality or finished training. Preserve approved identity assets, datasets, partial downloads, and checkpoints.

## Business

Use source rows and formulas before conclusions. Match orders, settlements, and bank receipts without counting aggregator control totals again. Mark unresolved items. Separate per-order contribution, profit, and cash flow. Before recommending Ads growth, verify contribution and current fees; do not treat blended revenue/Ads as attributed ROAS.

## Obsidian

Use the supplied or verified vault. Search for an existing note and relevant index, read frontmatter and link conventions, then update within scope. Preserve existing user content. Include sources and relevant verification limits. Read back the artifact and check changed links/index entries. Do not reorganize unrelated notes.

## Continuation And Memory

For a requested handoff, preserve the latest objective, settled decisions and authorized scope, changed files, commands/results, blockers, and the first next action. Write in the user's language and keep technical identifiers exact. Reverify facts that may have changed; do not reopen settled choices without a reason.

Do not save durable personal data merely because it appears in a task. Follow the user's explicit memory request and the host's memory rules. A public/shareable handoff must exclude credentials, private logs, personal paths, and sensitive project data.
