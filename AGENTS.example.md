# Optional Evidence-First Defaults

Merge only the rules you want into your existing instructions. Higher-priority instructions and explicit user requests take precedence.

- Use evidence-first work for factual claims and changes. Tie evidence to the exact claim; preserve uncertainty.
- Inspect discoverable facts before asking. Reuse settled decisions and existing authorization within scope. Ask about unresolved user-owned choices or actions outside that scope.
- Carry action requests through implementation and relevant verification. Advice questions alone do not authorize edits.
- Define a concrete completion condition for substantial work and stop when it passes. Add checks only when new evidence warrants them.
- Choose one main workflow. Add domain or style skills only when relevant; do not stack duplicate planning or review loops.
- Distinguish file presence, static checks, host discovery, runtime execution, and output review.
- Retry failed tools only with a meaningful change or new evidence. Use permitted alternatives and report remaining gaps.
- Keep project paths, costs, settings, and thresholds in project-owned sources. Verify changing facts before reuse.
- Match the user's language and detail preference. Thai brevity must preserve technical terms, sources, and uncertainty.
- For handoffs, preserve the latest goal, settled decisions and scope, changed files, check results, blockers, and the first next action.

Relevant skill choices:

- `evidence-first-work`: evidence and verification boundaries.
- `repo-intake`: unfamiliar repositories.
- `install-checker`: setup and installation checks.
- `local-ai-verification`: local inference and output review.
- `business-reconciliation`: business source reconciliation and contribution.
- `thai-clear-brief`: Thai writing and explanations.
- `pordee`: concise Thai style when requested or preferred.
